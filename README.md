# 王者荣耀决策实验室 · 数据工具箱（kplab）

只做一件事：**先把真实数据核对清楚，再谈胜率模型。**

本仓库内**不存在**任何假装已经训练好的 V(s) / Q(s,a) 模型，一个都没有。

- 只用 Python 标准库，Mac 自带 `python3` 就能跑，不需要 pip 安装
- 控制台跑在 8020 端口，只监听 127.0.0.1（和 LOL 项目的 8000 / 8010 错开）
- 抽帧要 ffmpeg、自动识别要 OCR 后端 —— **两个都不装也能开始工作**

## 先读这个

**[docs/为什么王者荣耀不能照抄LOL.md](docs/为什么王者荣耀不能照抄LOL.md)**

## 快速开始

只需要一条命令，其余全部在浏览器里点：

```bash
python3 -m kplab serve      # 打开 http://127.0.0.1:8020
```

**不需要装 ffmpeg，也不需要装任何识别工具就能开始标注。**

接手这个项目（人或 AI）请先跑一遍测试，47 个应该全过：

```bash
python3 -m unittest discover -s tests -v
```

它钉住的是下面「三条不许违反的规矩」。这三种错误**都不会报错**，
只会把数据悄悄弄坏，所以必须靠测试守着。

也可以全部用终端：

```bash
python3 -m kplab doctor                       自检：装了什么、还缺什么
python3 -m kplab new  KPL2026_AG_vs_EST_G1    建立一场比赛
python3 -m kplab frames <编号> --video x.mp4  从录像抽帧（要 ffmpeg）
python3 -m kplab check  <编号>                完整性与可信度检查
python3 -m kplab state  <编号> --minute 10    观测 → State，并打印第 10 分钟
python3 -m kplab evaluate <编号>              人工标注 vs 机器识别，看识别准不准
python3 -m kplab rules                        查看 / 核对游戏常量
```

## 模块

| 文件 | 作用 |
| --- | --- |
| `paths.py` | 定位 data 目录 |
| `rules.py` | 游戏常量，每条都带「**是否被人核对过**」标记 |
| `schema.py` | **值 + 来源 + 置信度** 的三元组结构（本项目的核心设计） |
| `store.py` | gzip 落档；观测**只追加不改写** |
| `video.py` | ffmpeg 抽帧（没装就明确报错，不退回估算） |
| `hud.py` | HUD 区域标定（**没标定就拒绝识别**） |
| `ocr.py` | 可插拔识别后端 + 数字解析（读不出来返回「不知道」，不返回 0） |
| `state.py` | 观测 → 分钟级 State，**严格前向、无未来信息泄漏** |
| `check.py` | 三层检查：有没有 / 对不对 / 可不可信 |
| `annotate.py` | 人工标注，**零依赖**，产出 ground truth |
| `evaluate.py` | 拿人工标注当标尺，量 OCR 的准确率 |
| `minimap.py` | 小地图找人：认位置，**不认英雄**（认不出来，也不假装） |
| `server.py` + `web/` | 控制台、标注页、标定页、逐帧核对页 |

## 三条不许违反的规矩

### 1. 每个数字都要说清楚「你怎么知道的」

LOL 的 `totalGold = 8421` 是 Riot 给的，是事实。
这边的 `8421` 是从记分板上认出来的，可能是 `3421`。

所以每个可观测字段都是三元组：值 + 来源（人工/识别/沿用/推算）+ 置信度。
显示时，**可信、存疑、未知三种必须长得不一样**。

### 2. 「没读到」不是 0

这一帧没认出红方经济，如果写成 0，经济差立刻变成 +12000 ——
一个巨大的假优势，而且看起来完全正常，任何一步都不会报错。

没读到就是 `None`。参与计算时结果也是 `None`。

### 3. 不许用后面的帧回头修前面的帧

第 5 帧读出经济 3000、第 6 帧读出 2000，必有一错。
「用第 6 帧修第 5 帧」曲线会更好看，但那是拿未来改过去 ——
这样训出来的模型在真实对局里（那时没有第 6 帧）根本没法复现。

坏读数被丢弃并沿用旧值，**第 5 帧写下之后永不改动**。

## 五种中立资源，五个计数器

LOL 项目有一个安静的 bug：先锋（RIFTHERALD）和虚空幼虫（HORDE）
被算进了大龙（barons），开局吃 6 个幼虫显示「大龙 6 条」。
它不报错，只是把训练数据弄坏。

王者荣耀更容易犯这个错，所以这五种**故意各占一行，绝不合并**：

暴君 · 黑暗暴君 · 主宰 · 风暴龙王 · 先知主宰

## 还没做的部分

V(s) 胜率模型、胜率曲线、行为抽象、Q(s,a)、Regret **全部尚未实现**。

**小地图只做了一半**：能认出「这里有一个蓝方标记」，
但认不出**那是哪个英雄**。所以「入侵野区值不值」还是答不了 ——
那需要知道敌方打野这个具体的人在哪。「敌方半区出现了几个人」倒是能答了。

而且到目前为止，**一场真实的王者荣耀比赛都还没进过这个系统**。
