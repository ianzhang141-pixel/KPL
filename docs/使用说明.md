# 使用说明（零基础分步操作）

> 这份文档假设你**完全没有编程基础**。
> 每一步都会说清楚：在哪里操作、按什么键、看到什么算成功。

---

## 你需要准备的

只有一样：**一场王者荣耀比赛的录像**，或者能在网上播放的比赛回放。

不需要装 ffmpeg，不需要装 Python 包，不需要 API Key。
（后面如果想让机器自动读数字，才需要装东西。第一遍先不用管。）

---

## 第一步：打开终端

「终端」是 Mac 自带的一个程序，长得像一个白底或黑底的方框。

1. 按住键盘上的 `Command` 键，再按一下空格键
2. 屏幕中间会出现一个搜索框
3. 输入 `终端` 两个字（或者英文 `Terminal`）
4. 按回车

一个窗口会打开，里面有一些文字和一个闪烁的光标。就是它了。

---

## 第二步：进入这个项目的文件夹

在终端里输入下面这行，然后按回车。
把 `~/KPL` 换成你实际放这个项目的位置：

```
cd ~/KPL
```

**怎么算成功：** 没有任何红色的错误文字出现，光标前面的路径变了。

如果出现 `No such file or directory`，说明路径不对。
最简单的办法：在终端里输入 `cd ` （注意 cd 后面有一个空格，别按回车），
然后把项目文件夹从访达里**直接拖进终端窗口**，路径会自动填上，再按回车。

---

## 第三步：启动控制台

输入这行，按回车：

```
python3 -m kplab serve
```

**怎么算成功：** 终端里出现一个方框，里面写着

```
王者荣耀决策实验室：http://127.0.0.1:8020
```

**这个终端窗口不要关，也不要按其他键。** 它关了网页就打不开了。
下面的操作全部在浏览器里做。

如果它提示 `Address already in use`（端口被占用），
说明已经开着一个了，直接跳到第四步。

---

## 第四步：在浏览器里打开控制台

打开 Chrome 或 Safari，在地址栏输入：

```
127.0.0.1:8020
```

按回车。应该看到一个深色的页面，标题是「王者荣耀决策实验室 · 数据控制台」。

页面上会显示两个「未安装」，分别是 ffmpeg 和自动识别 —— **这是正常的，不用管**。
第一遍走流程完全不需要它们。

---

## 第五步：建立一场比赛

在页面上找到「3 建立一场比赛」那一块。

1. **比赛编号**：写一个你自己看得懂的名字，比如 `KPL2026_AG_vs_EST_G1`
   （只能用英文字母、数字、下划线、短横线，不要用中文和空格）
2. **蓝方战队 / 红方战队**：随便填，比如 `AG` 和 `eStar`
3. **谁赢了**：**现在就填**。
   这是将来训练模型唯一的标签，事后补要重新翻录像找结果。
4. 点「建立」

**怎么算成功：** 下面出现绿色的「已建立 ...」，
并且页面最下面的「比赛清单」里出现了这一行。

---

## 第六步：开始标注（这是最重要的一步）

点页面顶部的「标注页」链接。

### 怎么操作

1. **另开一个窗口播放你的比赛录像**，和标注页并排放着
2. 把录像暂停在某个时刻，比如 2 分 00 秒
3. 在标注页的「这一帧的比赛时间」里填 `02:00`
4. 照着录像画面，把看得清的数字填进去：
   - 记分板上双方的总经济
   - 双方的击杀数
   - 如果看得清，填几个人的等级
5. 如果这段时间里有人拿了暴君或推了塔，在「事件」那里加一条
6. 点「保存这一帧」

然后把录像往后拖 30 秒，重复上面的步骤。

### 三条要记住的规矩

**① 看不清就留空，千万不要猜。**

留空会被记成「不知道」，这是正确的。
瞎填一个数才是灾难 —— 人工填的数字带着最高的可信度进入后面所有环节，
错了以后没有任何一步能发现它。

**② 暴君和主宰是两个不同的东西，别混。**

暴君在下路河道，主宰在上路河道。
黑暗暴君是暴君的强化版，风暴龙王是主宰的后期形态。
这四个在系统里是**四个独立的计数器**，填错了数据就坏了。

（LOL 那个项目就吃过这个亏：先锋和幼虫被算成了大龙，
界面上显示「大龙 6 条」，用那份数据训出来的模型是坏的。）

**③ 先标 10~15 帧就够了，不用标完整场。**

第一遍的目的是**把流程走通、看看这活儿有多累**，不是产出完整数据。

---

## 第七步：看看数据对不对

回到终端。**不要关掉正在跑控制台的那个窗口** ——
按 `Command + T` 开一个新标签页，然后：

```
cd ~/KPL
python3 -m kplab check KPL2026_AG_vs_EST_G1
```

（把编号换成你自己填的那个）

会打印一份中文报告，告诉你：
标了多少帧、字段覆盖率多少、有没有不可能出现的值、有没有读数被拒绝。

**报告里出现「❌ 不通过」不代表你做错了。**
第一次标 10 帧，覆盖率肯定不高，这是正常的。
重点看有没有「违反游戏规则的值」那一段 —— 那才是真的填错了。

---

## 第八步：逐帧核对

回到浏览器，点顶部的「逐帧核对页」。

上面会显示每一帧的完整局势。注意三种颜色：

- **白色**：可信的值
- **黄色带问号**：可信度不够，只能参考
- **灰色的横线**：不知道

第一遍全部人工标注的话，应该都是白色的（因为人工填的可信度最高）。

---

## 常见问题

**问：终端里出现一大堆红色文字怎么办？**
把那些文字**整段复制**下来贴给 AI。不要只说「报错了」，
红色文字里通常已经写清楚了原因。

**问：控制台页面打不开？**
检查跑 `serve` 的那个终端窗口还在不在、有没有被关掉。

**问：一定要装 ffmpeg 吗？**
不用。装了它可以自动把录像切成图片，标注时不用手动拖进度条，方便一些。
但不装完全不影响标注。

**问：什么时候能看到胜率曲线？**
现在还没有。整个仓库里没有任何模型 —— 这是有意的。
在数据被核对清楚之前做出来的曲线是假的，那正是这个项目想避免的事。
